# 글 작성 규칙

## 0단계: 키워드 확인 (글 쓰기 전 필수 — 로알남 방식)
1. 제목에서 핵심 검색 키워드를 정한다 (예: "해외직구 관세 기준", "목록통관 일반통관 차이").
2. WebSearch로 그 키워드의 **구글 상위노출 글 2~3개를 훑어본다**: 어떤 내용을 다루는지, 뭐가 빠져 있는지.
3. 상위 글에 없는 **차별화 포인트를 최소 1개** 정하고 본문에 반영한다 (실제 계산 예시, 최신 규정, 표 정리, 실무자 관점 등).
4. 핵심 키워드는 제목 앞쪽 + 첫 문단 + 소제목 1개 이상에 자연스럽게 배치한다.

## ⛔ 획일감 금지 (2026-08-08 애드센스 거절 후 최우선 규칙)
애드센스가 "가치 없는 콘텐츠"로 거절한 최대 원인은 **모든 글이 똑같은 뼈대로 찍어낸 느낌**이었다. 앞으로 모든 글은 서로 달라 보여야 한다. 아래를 반드시 지킨다.
- **도입 방식을 글마다 바꾼다**: 큰따옴표 인용으로만 시작하지 마라. 오해 깨기·실계산 먼저 보여주기·시나리오 묘사·정의로 차분히 시작·2인칭 상황·비교 관점 등 매번 다른 방식으로 연다.
- **뼈대를 고정하지 마라**: `도입→h2 3~5개→표→"정리하면"→고지문`을 매번 그대로 쓰면 안 된다. 어떤 글은 Q&A, 어떤 글은 단계별, 어떤 글은 사례 중심, 어떤 글은 체크리스트 중심으로.
- **마무리에 "정리하면 —"을 상투적으로 쓰지 마라. "다음 글에서는 ~ 다루겠습니다" 예고는 쓰지 마라.**
- **고지문(면책)도 매번 똑같은 문장을 복붙하지 말고 이 글에 맞게 새로 쓴다** (관세청 링크와 125는 포함하되 표현을 바꾼다).
- **필자 관점(정직하게)**: 실무자 시선 1~2군데를 넣되("상담하다 보면 이 부분을 가장 많이 헷갈려하십니다") **없는 날짜·개인 일화·측정치를 지어내지 마라.** 관찰·판단·주의는 담되 사실은 참이어야 한다.

## 구조 (지침 — 위 '획일감 금지'가 우선한다)
1. **도입 후킹 (2~3문장)**: 독자의 실제 고민/궁금증으로 시작. 절대 "오늘은 ~에 대해 알아보겠습니다" 같은 뻔한 도입 금지. (도입 방식은 글마다 다르게 — 위 규칙 참조)
2. **소제목(h2) 3~5개**: 각 소제목 아래 2~4문단. 소제목은 그 자체로 정보가 되게 (예: "150달러 넘으면 전체 금액에 과세된다" — "과세 기준"처럼 밋밋하게 쓰지 말 것). 질문형·단정형·숫자형을 글마다 섞는다.
3. **본문 길이: 공백 제외 1,700자 이상** (한글 기준, 2,000~2,600자 권장). 애드센스 심사에는 얇은 글이 불리하다.
4. **표 또는 리스트 1개 이상**: 숫자·기준·비교는 표(`<figure class="wp-block-table"><table>`)로.
5. **독자가 흔히 착각·실수하는 포인트 1~2개**를 짚는다 (차별화 + 체류시간). 단, 매 글 똑같은 소제목·형식으로 넣지 말고 자연스럽게 녹인다.
6. **마무리**: 핵심을 정리하되 "정리하면 —" 상투구·다음 글 예고는 쓰지 않는다. 실행형 체크리스트·판단 기준·안심 메시지 등 글에 맞는 방식으로 닫는다. (내부링크는 관련 글이 실제 발행된 경우에만)

## 시인성(가독성) 규칙 (2026-08-19 사용자 지시 — 30~50대 누구 눈에도 핵심이 잘 띄게)
핵심이 한눈에 들어오게 만든다. 밋밋한 회색 벽 같은 글 금지.
- **핵심 수치·결론은 `<strong>`으로 굵게**: 면세 기준(150달러·200달러), 수량(6병), 세율(관세 8%·부가세 10%), "전체 금액에 과세" 같은 결정적 문구는 굵게 처리해 스캔만 해도 보이게. (단, 한 문단에 굵은 게 너무 많으면 오히려 안 보임 — 진짜 중요한 것만.)
- **글마다 '핵심 콜아웃 박스' 1개**: 그 글에서 가장 중요한 한 문장을 아래 박스로 감싸 본문 흐름 중 적절한 위치(대개 핵심 h2 아래)에 넣는다. 큰 글씨+골드 라인으로 눈에 띈다.
  ```html
  <p style="margin:1.4em 0;padding:14px 18px;background:#fbf8f0;border-left:5px solid #c9a44a;border-radius:6px;font-size:17px;line-height:1.7;"><strong>핵심</strong> — 여기에 그 글에서 가장 중요한 한 문장.</p>
  ```
- **문단은 짧게**: 한 문단 3~4문장 이내. 길면 쪼갠다(모바일·폭넓은 연령 가독).
- **h2 소제목은 그 자체로 결론이 보이게**(기존 규칙) — 소제목만 훑어도 글이 요약되게.
- 과하게 알록달록/형광펜 남발은 금지. 강조는 **골드 라인 박스 + 굵은 글씨** 정도로 절제 있게, 톤은 신뢰감 유지.
- 상단 '한눈 요약' 박스와 하단 FAQ는 파이프라인이 자동 렌더(크게·또렷하게) — 본문 콜아웃과 역할이 겹치지 않게, 콜아웃은 요약과 다른 '실전 핵심'으로.

## GEO 최적화 (답변엔진 인용 — 필수, Orca 구조 이식)
SEO가 "검색 순위"라면 GEO는 "ChatGPT·Perplexity·구글 AI 개요가 우리 글을 **인용**하게" 만드는 것. 인용되려면 **뽑아 쓰기 좋은 구조**여야 한다. drafts/ 파이프라인이 아래 두 필드를 자동 렌더하므로 **글마다 반드시 채운다**.
- **`answer_summary` (상단 한눈 요약)**: 글의 핵심을 2~3문장으로, **결론부터** 압축. 파이프라인이 본문 맨 위 골드 박스로 렌더한다. 답변엔진이 이 박스를 그대로 인용하기 좋게, 질문에 대한 답을 먼저 제시하는 문장으로 쓴다. (예: "직구 관세는 물품가 15만원(미화 150달러, 미국은 200달러) 초과 시 부과됩니다. 초과하면 면세가 아니라 전체 금액에 과세되는 점이 핵심입니다.")
- **`faq` (하단 자주 묻는 질문 3문항)**: 독자가 **실제로 검색창·챗봇에 칠 법한 질문** 3개와 2~3문장 답. 파이프라인이 하단 FAQ 섹션 + `FAQPage` JSON-LD(구조화 데이터)로 렌더 → 구글 리치결과 + 답변엔진 인용 대상이 된다. 질문은 본문에서 다룬 내용과 겹쳐도 되지만 **답은 결론부터 명확하게**. 수치·규정은 정확히.
- 요약·FAQ의 수치는 본문과 **모순되지 않게**, 지어낸 값 금지. 본문에 이미 요약/FAQ 성격의 문단이 있어도 프론트매터 필드는 별도로 채운다(렌더 위치가 다름).

## AI 티 제거(humanize) — 초안 커밋 전 필수
글을 다 쓴 뒤 drafts/에 커밋하기 **직전**에 `/humanize-korean` 스킬로 본문을 한 번 훑어 "AI가 쓴 티"를 지운다. 이건 획일감 금지 규칙의 문장 단위 실행판이다.
- **반드시 제거(S1)**: "결론적으로/종합하면", "시사하는 바가 크다", "주목할 만하다", "~라 할 수 있다", 이중피동("되어진다"), 기계적 "첫째·둘째·셋째".
- **반복되면 제거(S2)**: 번역투 "~를 통해/~에 있어서/가지고 있다", 문두 접속사 연발("또한/따라서/그리고"), "~할 수 있을 것으로 보인다" 류 다중 완곡.
- **줄이기(S3)**: 과도한 볼드·이모지·불릿, "매우/정말" 수식, 형식명사("것이다/점/수/바") 남발. 문장 길이·종결어미는 일부러 불균일하게(사람 글의 리듬).
- **철칙**: 의미·주장·**수치(관세율·면세기준·날짜)·고유명사는 100% 보존**. 탐지된 부분만 수술적으로 고치고, 변경률 30% 넘으면 과윤문 — 되돌린다.
- 규칙 상세: `.claude/skills/humanize-korean/references/`(quick-rules·taxonomy·playbook). 발행 파이프라인의 `humanize_gate.py`가 커밋 후에도 자동 점검해 경고한다.

# 이미지 스타일 다양화 (획일감 금지 — 2026-08-17 사용자 지시)

썸네일·본문이미지가 **매번 다크네이비+골드**로만 나오면 글 획일감처럼 이미지도 찍어낸 느낌을 준다. 광고급 품질(브랜드 로고 금지, 썸네일 한글 텍스트 정확)은 유지하되 **배경색·톤·장면을 글마다 돌려가며** 쓴다. 한 글의 썸네일과 본문이미지는 **같은 팔레트**로 통일하되, 글이 바뀌면 팔레트도 바꾼다.

**팔레트 로테이션 (글마다 하나 선택, 최근 3~4개 글과 겹치지 않게):**
- **A. 다크 프리미엄** — 딥네이비/차콜 + 골드, 시네마틱, 대리석. (밀수·처벌·고가품 등 무게 있는 주제)
- **B. 밝은 에디토리얼** — 크림/화이트/소프트 그레이 배경 + 우드·파스텔, 자연광, 미니멀 플랫레이. (가이드·절차·기초 설명)
- **C. 웜 선샤인** — 웜 샌드/테라코타/머스터드/코랄 + 따뜻한 햇살. (여행·쇼핑의 즐거움, 선물)
- **D. 프레시 쿨** — 민트/틸/세이지/스카이블루 + 청량한 톤. (건강·영양제·깔끔한 정보)
- **E. 플레이풀** — 밝고 채도 높은 컬러 블록, 친근한 실사/세미 일러스트, 위트 있는 소품. (가볍게 푸는 주제)

**장면도 매번 바꾼다**: 데스크 플랫레이만 반복 금지. 공항·여행가방, 손 언박싱, 재래시장·온라인마켓 화면, 주방 카운터(영양제·식품), 세관 데스크, 스마트폰 화면, 현관 앞 택배 등 글 내용에 맞는 장면으로. 가끔은 재치 있는 연출도 좋다(신뢰 정보 톤은 유지).

**바뀌는 건 '색과 장면'이지 품질이 아니다** — 어떤 팔레트든 좋은 조명·얕은 심도·광고급 퀄리티는 공통. 실제 브랜드 로고·상표는 어느 경우에도 금지.

**자유롭게 (2026-08-19 사용자 지시)**: 위 A~E 팔레트는 **고정 사이클이 아니라 예시·가이드**일 뿐이다. 색뿐 아니라 **그림체 자체**(실사·에디토리얼 사진·플랫/세미 일러스트·수채·아이소메트릭 등)도 글에 맞으면 언제든 바꿔도 된다. 규칙의 핵심은 딱 하나 — **한 스타일에 편향되지 말 것.** 굳이 순서를 지키거나 매번 팔레트를 억지로 바꿀 필요는 없고, 전체적으로 다양하게만 유지하면 된다(품질·로고 금지·썸네일 한글 정확은 유지).

# 본문 이미지 규칙 (글마다 1장 필수 — 썸네일과 별도)

글의 **가장 중요한 핵심 대목**(예: 계산 예시, 규정의 결정적 포인트, 절차의 갈림길)에 어울리는 이미지 1장을 OpenAI(gpt-image-2)로 생성해 본문 중간에 넣는다.

- 위치: 그 글에서 독자에게 가장 중요한 h2 섹션의 시작 부분 (도입부 바로 아래 금지 — 썸네일과 겹쳐 보임)
- 스타일: 그 글의 썸네일과 **같은 팔레트**(위 '이미지 스타일 다양화'에서 고른 A~E)로 톤을 맞추되, 헤드라인 텍스트가 아니라 **핵심 내용을 장면으로 보여주는 실사풍 연출** (예: 세관 검사대 위의 택배상자, 저울 위의 영양제 병 6개, 관세 고지서와 계산기)
- **한글 텍스트는 넣지 않는다** (오타 위험 — 텍스트는 썸네일 담당). 숫자만 크게 들어가는 연출은 허용 (예: '6', '150').
- 크기 1536x1024, quality high. 생성 후 Read 도구로 열어 어색한 부분(왜곡된 손, 깨진 글자 등) 검수, 문제 시 재생성 (최대 2회).
- Pillow로 JPEG 변환(quality 88, 400KB 이하) → 워드프레스 media 업로드 (파일명: `슬러그-body.jpg`)
- 본문 삽입 HTML: `<figure class="wp-block-image size-large"><img src="업로드된 source_url" alt="글 핵심을 설명하는 한 문장"/></figure>`
- 임시파일은 글 번호 접두어 필수 (예: `post12-body.png`) — 썸네일 규칙과 동일.

# 썸네일 제작 규칙 (글마다 1장 필수)

## 1순위: OpenAI 이미지 생성 (gpt-image-2)

스타일 = **고급 프리미엄** (사용자 확정 지시: "아주 고급스럽게"): 최고급 경제지 표지 / 명품 광고 같은 세련된 미장센. 유치한 클릭베이트 느낌 금지.

**썸네일은 글당 딱 1장만 생성한다** (사용자 지시). 여러 시안을 만들지 말 것. 한 번에 좋은 프롬프트로 1장 생성 → 한글 오타만 검수 → 문제 있을 때만 재생성(최대 2회).

프롬프트 작성 규칙 (한국어로 작성):
- "프리미엄 잡지 표지 스타일의 블로그 썸네일. 가로형 구도." 로 시작 (팔레트에 따라 '최고급 경제지'·'밝은 라이프스타일 매거진' 등으로 변주)
- 분위기 키워드: **위 '이미지 스타일 다양화'에서 고른 팔레트(A~E)에 맞는 배경색·톤** + 그에 어울리는 조명(시네마틱 또는 밝은 자연광), 얕은 심도, 8K 광고급 품질. (다크네이비+골드+대리석은 A 팔레트일 때만 — 매번 쓰지 말 것)
- 헤드라인: 핵심 문구를 **금박(골드 포일) 또는 실버 메탈 질감의 큰 한글 텍스트**로. 대비 구도면 가운데 우아한 금색 세로 라인으로 분할.
- 글 제목의 핵심 문구를 **짧은 한글 텍스트 2~5개**로 지정. 문구가 길면 AI가 글자를 틀리므로 각 문구는 2~10자로 짧게.
- 프롬프트 끝에 "한글 텍스트는 정확하게: <문구1> / <문구2> / ..." 형태로 명시
- 오브젝트: 글 주제 관련 실사풍 고급 소품 (크래프트 택배상자, 마호가니 세관 도장, 왁스 실링 서류, 비행기, 컨테이너선 미니어처 등)을 스포트라이트 아래 정갈하게 배치
- quality는 'high' 사용

생성 절차 (Bash + curl):
1. `C:\CLAUDE\제이로그\wp-api-config.md`에서 OpenAI API 키를 읽는다
2. 요청 JSON을 파일로 작성 (한글 인코딩 문제 방지): `{"model":"gpt-image-2","prompt":"...","size":"1536x1024","quality":"medium"}`
3. `curl https://api.openai.com/v1/images/generations -H "Authorization: Bearer <키>" -H "Content-Type: application/json" --data-binary @파일` → 응답의 `b64_json`을 base64 디코드해 PNG 저장
4. **Read 도구로 이미지를 열어 눈으로 검증**: 한글 문구에 오타·깨진 글자가 없는지, 구도가 좋은지. 문제 있으면 프롬프트를 고쳐 재생성 (최대 2회)
5. Pillow로 JPEG 변환해 용량 최적화: `Image.open(png).convert('RGB').save(jpg,'JPEG',quality=88,optimize=True)` (400KB 이하 목표)
6. 워드프레스 업로드: `curl -X POST .../wp-json/wp/v2/media -H "Content-Disposition: attachment; filename=\"슬러그-thumb.jpg\"" -H "Content-Type: image/jpeg" --data-binary @jpg파일` → media id를 `featured_media`로 지정
- API가 결제 한도 오류(Billing hard limit)를 내면: 사용자에게 OpenAI 크레딧 충전이 필요하다고 보고하고, 아래 2순위 방식으로 대체한다.

## 2순위 (폴백): SVG 에디토리얼 일러스트 — OpenAI API 실패 시에만
- 크기: **1200×630** viewBox의 SVG로 제작
- **밀도 높게**: 최소 40개 이상의 요소(도형·레이어). 빈 배경에 아이콘 하나 금지.
- 필수 기법: 2~3색 그라디언트 배경, 전경/중경/배경 3레이어, feTurbulence 질감, 부드러운 그림자, 장식 디테일
- 팔레트: 딥네이비 `#1a2b4a`, 웜샌드 `#f4b942`, 코랄 `#e8604c`, 크림 `#faf3e7`, 세이지 `#7fa98e`
- **텍스트는 넣지 않는다** (한글 폰트 렌더링 편차 방지)

SVG 렌더링 & 업로드 (설치 불필요):
1. `mcp__Claude_Browser__preview_start` 로 `https://jaylog.co.kr/` 탭 열기 (이미 열려 있으면 재사용)
2. `javascript_tool`로 아래 실행 — SVG 문자열을 넣고 캔버스 렌더 → 같은 자리에서 미디어 업로드:
```js
(async () => {
  const svg = `...SVG 전체...`;
  const blob = new Blob([svg], {type: 'image/svg+xml'});
  const img = new Image();
  await new Promise((res, rej) => { img.onload = res; img.onerror = rej; img.src = URL.createObjectURL(blob); });
  const canvas = document.createElement('canvas');
  canvas.width = 1200; canvas.height = 630;
  canvas.getContext('2d').drawImage(img, 0, 0, 1200, 630);
  const png = await (await fetch(canvas.toDataURL('image/png'))).blob();
  const res = await fetch('/wp-json/wp/v2/media', {
    method: 'POST',
    headers: {
      'Authorization': 'Basic ' + btoa('claude:APP_PASSWORD'),  // wp-api-config.md의 값
      'Content-Disposition': 'attachment; filename="SLUG-thumb.png"',
      'Content-Type': 'image/png'
    },
    body: png
  });
  const j = await res.json();
  return JSON.stringify({status: res.status, id: j.id, url: j.source_url});
})()
```
3. 반환된 media id를 글의 `featured_media`로 지정
4. 업로드 후 이미지를 눈으로 확인 — 밀도가 낮거나 어색하면 다시 그린다 (최대 2회 재시도)

   - `categories: [<글계획.md의 카테고리 id>]`, `featured_media: <id>`
   - `tags`: 글의 핵심 키워드 4~6개를 태그로 지정. REST API의 `tags`는 태그 id 배열이므로, 먼저 각 키워드를 `POST /wp-json/wp/v2/tags {"name":"키워드"}`로 생성(이미 있으면 기존 id 사용, 중복 생성 오류 시 응답의 기존 id 활용)해 id를 얻은 뒤 배열로 넣는다. 키워드는 실제 검색어 형태로 (예: "해외직구 관세", "관부가세 계산", "개인통관고유부호").
   - `excerpt`: 검색결과에 보일 요약 1~2문장
   - `meta`: `{"rank_math_title": "제목 | 제이로그", "rank_math_description": "155자 이내 요약", "rank_math_focus_keyword": "핵심키워드"}` (Rank Math가 meta 등록을 지원하지 않아 실패해도 무시하고 진행)
5. 완료 보고: 글 제목, 초안/발행 상태, 편집 링크(`https://jaylog.co.kr/wp-admin/post.php?post=<id>&action=edit`), 썸네일 URL, **지정한 키워드(태그) 목록**
6. `C:\CLAUDE\제이로그\` 의 작성 현황 파일에 완료 기록 추가
