# 글 작성 규칙

## 0단계: 키워드 확인 (글 쓰기 전 필수 — 로알남 방식)
1. 제목에서 핵심 검색 키워드를 정한다 (예: "해외직구 관세 기준", "목록통관 일반통관 차이").
2. WebSearch로 그 키워드의 **구글 상위노출 글 2~3개를 훑어본다**: 어떤 내용을 다루는지, 뭐가 빠져 있는지.
3. 상위 글에 없는 **차별화 포인트를 최소 1개** 정하고 본문에 반영한다 (실제 계산 예시, 최신 규정, 표 정리, 실무자 관점 등).
4. 핵심 키워드는 제목 앞쪽 + 첫 문단 + 소제목 1개 이상에 자연스럽게 배치한다.

## 구조 (필수)
1. **도입 후킹 (2~3문장)**: 독자의 실제 고민/궁금증으로 시작. "~아셨나요?", 실제 상황 예시, 의외의 사실. 절대 "오늘은 ~에 대해 알아보겠습니다" 같은 뻔한 도입 금지.
2. **소제목(h2) 3~5개**: 각 소제목 아래 2~4문단. 소제목은 그 자체로 정보가 되게 (예: "150달러 넘으면 전체 금액에 과세된다" — "과세 기준"처럼 밋밋하게 쓰지 말 것).
3. **본문 길이: 공백 포함 1,500~2,500자** (한글 기준). 길게 늘어놓지 말고 밀도 있게. 애드센스 심사에는 얇은 글이 불리하므로 1,500자 미만 금지.
4. **표 또는 리스트 1개 이상**: 숫자·기준·비교는 표(`<figure class="wp-block-table"><table>`)로.
5. **"많이들 실수하는 것" 고정 코너**: 매 글에 독자가 흔히 착각·실수하는 포인트 1~2개를 짚는 단락 또는 소제목을 넣는다 (차별화 + 체류시간).
6. **마무리 = 3줄 요약 + 체크리스트**: 핵심 요약 2~3줄, 가능하면 "○○ 전 확인 3가지" 같은 실행형 체크리스트로 마무리. 다음에 읽으면 좋은 주제 예고 (내부링크는 관련 글이 실제 발행된 경우에만).

## HTML 형식 (Gutenberg 호환)
- 소제목: `<h2 class="wp-block-heading">` 사용 (테마가 자동으로 두껍고 크게 렌더링)
- 세부 소제목: h2 아래 하위 항목이 여러 개면 `<h3 class="wp-block-heading">`으로 위계를 만든다 (H1제목→H2→H3 구조가 애드센스 심사·SEO에 유리). 글씨 크기 조절로 흉내내지 말고 반드시 정식 heading 태그 사용.
- 문단: `<p>`, 강조: `<strong>` (문단당 최대 1~2회)
- 표: `<figure class="wp-block-table"><table>...</table></figure>`
- 리스트: `<ul>`/`<ol>`

## 체류시간 원칙 (구글 최신 알고리즘 대응)
- 독자가 오래 머물게 만드는 요소를 의도적으로 배치: 표, 리스트, 실제 계산 예시, "많이들 착각하는 것" 코너
- 첫 화면(도입부)에서 이 글이 답을 준다는 확신을 줘야 이탈하지 않는다
- 발행 글이 쌓이면 관련 글 내부링크 1~2개 삽입 (실제 발행된 글만)

## 내용 원칙
- 관세율·면세기준·규정 수치는 **정확해야 함**. 불확실하면 WebSearch로 관세청/공식 출처 확인.
- 연도가 들어가는 규정은 "2026년 기준" 명시.
- 글 말미에 한 줄 고지: `<p><em>본 글은 일반 정보 제공 목적이며, 개별 사안은 관세청(국번없이 125) 또는 관세사 확인이 필요합니다.</em></p>`
- 다른 블로그 복붙 금지. 모든 문장은 직접 작성 (애드센스 중복 콘텐츠 탈락 사유).
- **과장 표현 자제**: "완벽 정리", "총정리", "무조건", "100%", "충격" 같은 절대·낚시형 표현은 제목·본문에서 피한다. 신뢰형 정보 문체 유지. (기존 발행글 제목은 URL·유입 보호를 위해 소급 수정하지 않음)
- **가짜 경험담 금지**: 실존 인물처럼 읽히는 사례를 지어내지 않는다. 예시가 필요하면 "예를 들어 ~한 경우를 보겠습니다"처럼 가상의 예시임이 드러나는 화법으로 쓴다.
- **업데이트 전제**: 규정이 바뀌는 주제이므로 글에 "○년 ○월 기준"을 명시하고, 규정 변경 확인 시 기존 글도 수정한다. 수정 시 수정일이 갱신되도록 저장.

- 위치: 그 글에서 독자에게 가장 중요한 h2 섹션의 시작 부분 (도입부 바로 아래 금지 — 썸네일과 겹쳐 보임)
- 스타일: 썸네일과 같은 프리미엄 톤(다크 네이비+골드, 시네마틱 조명)을 유지하되, 헤드라인 텍스트가 아니라 **핵심 내용을 장면으로 보여주는 실사풍 연출** (예: 세관 검사대 위의 택배상자, 저울 위의 영양제 병 6개, 관세 고지서와 계산기)
- **한글 텍스트는 넣지 않는다** (오타 위험 — 텍스트는 썸네일 담당). 숫자만 크게 들어가는 연출은 허용 (예: '6', '150').
- 크기 1536x1024, quality high. 생성 후 Read 도구로 열어 어색한 부분(왜곡된 손, 깨진 글자 등) 검수, 문제 시 재생성 (최대 2회).
- Pillow로 JPEG 변환(quality 88, 400KB 이하) → 워드프레스 media 업로드 (파일명: `슬러그-body.jpg`)
- 본문 삽입 HTML: `<figure class="wp-block-image size-large"><img src="업로드된 source_url" alt="글 핵심을 설명하는 한 문장"/></figure>`
- 임시파일은 글 번호 접두어 필수 (예: `post12-body.png`) — 썸네일 규칙과 동일.

# 썸네일 제작 규칙 (글마다 1장 필수)

## 1순위: OpenAI 이미지 생성 (gpt-image-2)

스타일 = **고급 프리미엄** (사용자 확정 지시: "아주 고급스럽게"): 최고급 경제지 표지 / 명품 광고 같은 세련된 미장센. 유치한 클릭베이트 느낌 금지.

**썸네일은 글당 딱 1장만 생성한다** (사용자 지시). 여러 시안을 만들지 말 것. 한 번에 좋은 프롬프트로 1장 생성 → 한글 오타만 검수 → 문제 있을 때만 재생성(최대 2회).

프롬프트 작성 규칙 (한국어로 작성):
- "최고급 프리미엄 경제지 표지 스타일의 블로그 썸네일. 가로형 구도." 로 시작
- 분위기 키워드 필수 포함: 럭셔리한 다크 네이비 배경, 시네마틱 스튜디오 조명, 은은한 금색 입자, 반사되는 검은 대리석 바닥, 8K 광고 촬영 품질, 얕은 심도
- 헤드라인: 핵심 문구를 **금박(골드 포일) 또는 실버 메탈 질감의 큰 한글 텍스트**로. 대비 구도면 가운데 우아한 금색 세로 라인으로 분할.
- 글 제목의 핵심 문구를 **짧은 한글 텍스트 2~5개**로 지정. 문구가 길면 AI가 글자를 틀리므로 각 문구는 2~10자로 짧게.
- 프롬프트 끝에 "한글 텍스트는 정확하게: <문구1> / <문구2> / ..." 형태로 명시
- 오브젝트: 글 주제 관련 실사풍 고급 소품 (크래프트 택배상자, 마호가니 세관 도장, 왁스 실링 서류, 비행기, 컨테이너선 미니어처 등)을 스포트라이트 아래 정갈하게 배치
- quality는 'high' 사용

생성 절차 (Bash + curl):
1. `C:\CLAUDE\제이로그\wp-api-config.md`에서 OpenAI API 키를 읽는다
2. 요청 JSON을 파일로 작성 (한글 인코딩 문제 방지): `{"model":"gpt-image-2","prompt":"...","size":"1536x1024","quality":"medium"}`
3. `curl https://api.openai.com/v1/images/generations -H "Authorization: Bearer <키>" -H "Content-Type: application/json" --data-binary @파일` → 응답의 `b64_json`을 base64 디코드해 PNG 저장
4. **Read 도구로 이미지를 열어 눈으로 검증**: 한글 문구에 오타·깨진 글자가 없는지, 구도가 좋은지. 문제 있으면 프롬프트를 고쳐 재생성 (최대 2회)
5. Pillow로 JPEG 변환해 용량 최적화: `Image.open(png).convert('RGB').save(jpg,'JPEG',quality=88,optimize=True)` (400KB 이하 목표)
6. 워드프레스 업로드: `curl -X POST .../wp-json/wp/v2/media -H "Content-Disposition: attachment; filename=\"슬러그-thumb.jpg\"" -H "Content-Type: image/jpeg" --data-binary @jpg파일` → media id를 `featured_media`로 지정
- API가 결제 한도 오류(Billing hard limit)를 내면: 사용자에게 OpenAI 크레딧 충전이 필요하다고 보고하고, 아래 2순위 방식으로 대체한다.

## 2순위 (폴백): SVG 에디토리얼 일러스트 — OpenAI API 실패 시에만
- 크기: **1200×630** viewBox의 SVG로 제작
- **밀도 높게**: 최소 40개 이상의 요소(도형·레이어). 빈 배경에 아이콘 하나 금지.
- 필수 기법: 2~3색 그라디언트 배경, 전경/중경/배경 3레이어, feTurbulence 질감, 부드러운 그림자, 장식 디테일
- 팔레트: 딥네이비 `#1a2b4a`, 웜샌드 `#f4b942`, 코랄 `#e8604c`, 크림 `#faf3e7`, 세이지 `#7fa98e`
- **텍스트는 넣지 않는다** (한글 폰트 렌더링 편차 방지)

SVG 렌더링 & 업로드 (설치 불필요):
1. `mcp__Claude_Browser__preview_start` 로 `https://jaylog.co.kr/` 탭 열기 (이미 열려 있으면 재사용)
2. `javascript_tool`로 아래 실행 — SVG 문자열을 넣고 캔버스 렌더 → 같은 자리에서 미디어 업로드:
```js
(async () => {
  const svg = `...SVG 전체...`;
  const blob = new Blob([svg], {type: 'image/svg+xml'});
  const img = new Image();
  await new Promise((res, rej) => { img.onload = res; img.onerror = rej; img.src = URL.createObjectURL(blob); });
  const canvas = document.createElement('canvas');
  canvas.width = 1200; canvas.height = 630;
  canvas.getContext('2d').drawImage(img, 0, 0, 1200, 630);
  const png = await (await fetch(canvas.toDataURL('image/png'))).blob();
  const res = await fetch('/wp-json/wp/v2/media', {
    method: 'POST',
    headers: {
      'Authorization': 'Basic ' + btoa('claude:APP_PASSWORD'),  // wp-api-config.md의 값
      'Content-Disposition': 'attachment; filename="SLUG-thumb.png"',
      'Content-Type': 'image/png'
    },
    body: png
  });
  const j = await res.json();
  return JSON.stringify({status: res.status, id: j.id, url: j.source_url});
})()
```
3. 반환된 media id를 글의 `featured_media`로 지정
4. 업로드 후 이미지를 눈으로 확인 — 밀도가 낮거나 어색하면 다시 그린다 (최대 2회 재시도)

## 공통
- 자가검증 체크리스트의 썸네일 항목은 사용 방식(1순위/2순위)에 맞게 판단한다.
- 썸네일 스타일은 블로그 전체에서 일관되게 유지한다.

# 발행 절차

**⛔ 0순위 — 주제 사전 허가 (필수, 예외 없음)**: 순서는 반드시 ① 글계획.md에서 다음 후보 주제 5개를 골라 사용자에게 제시 → ② 허가 → ③ 작성 → ④ 예약. 허가 전에는 글 작성·drafts 커밋·예약 무엇도 하지 않는다 (예약만 먼저 걸어두는 것도 금지). 사용자가 특정 주제를 직접 지시한 경우는 그 지시가 곧 허가다.

발행 페이스 규칙: **하루 최대 3개**. 한꺼번에 몰아 발행하지 않는다 (애드센스 심사에 부자연스럽게 보임). 여러 개를 쓰더라도 초안으로 쌓아두고 나눠서 발행한다.

1. 주제 확정 (사전 허가받은 주제 중에서)
2. 0단계 키워드 확인 수행 + 필요시 WebSearch로 최신 규정 확인
3. 썸네일 제작 → 업로드 → media id 확보
4. REST API로 글 등록 (Bash + curl, JSON은 파일로 만들어 `--data-binary @file` 사용 — 한글 인코딩 문제 방지):
   - `title`, `content`, `status: "draft"` (기본은 초안; "바로 발행" 지시가 있을 때만 `publish`)
   - `categories: [<글계획.md의 카테고리 id>]`, `featured_media: <id>`
   - `tags`: 글의 핵심 키워드 4~6개를 태그로 지정. REST API의 `tags`는 태그 id 배열이므로, 먼저 각 키워드를 `POST /wp-json/wp/v2/tags {"name":"키워드"}`로 생성(이미 있으면 기존 id 사용, 중복 생성 오류 시 응답의 기존 id 활용)해 id를 얻은 뒤 배열로 넣는다. 키워드는 실제 검색어 형태로 (예: "해외직구 관세", "관부가세 계산", "개인통관고유부호").
   - `excerpt`: 검색결과에 보일 요약 1~2문장
   - `meta`: `{"rank_math_title": "제목 | 제이로그", "rank_math_description": "155자 이내 요약", "rank_math_focus_keyword": "핵심키워드"}` (Rank Math가 meta 등록을 지원하지 않아 실패해도 무시하고 진행)
5. 완료 보고: 글 제목, 초안/발행 상태, 편집 링크(`https://jaylog.co.kr/wp-admin/post.php?post=<id>&action=edit`), 썸네일 URL, **지정한 키워드(태그) 목록**
6. `C:\CLAUDE\제이로그\` 의 작성 현황 파일에 완료 기록 추가
